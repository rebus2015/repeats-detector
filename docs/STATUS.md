# Состояние проекта — 30 октября 2026

Локальный пилот собран и проверен: MinIO → RabbitMQ → Go service → PostgreSQL → RabbitMQ.
Пользователь выбрал локальный Docker Compose. Удалённое развёртывание не входит в текущий этап.

## Готово

- PCM WAV 16 кГц / mono / 16 бит обрабатывается в RAM, исходники не меняются.
- Спектральные отпечатки landmark-v2, временная проверка совпадений.
- Поиск по последним 60 минутам внутри scope/version; динамическая индексация частичных повторов.
- Оконный поиск длинных файлов, фильтр частых хешей, ограниченный fallback и защита от усечённого unique.
- PostgreSQL: идемпотентность задач, атомарные решение/индекс/outbox, миграция и отдельный runtime role.
- RabbitMQ: quorum input, confirms, manual Ack, стабильный event_id, повторы и DLQ.
- Publisher переиспользует соединение и восстанавливается после ошибки.
- CLI replay-dlq сохраняет чужие сообщения и подтверждает источник только после публикации.
- Очистка несколькими ограниченными батчами, timeout, graceful shutdown, readiness/health.
- OTel traces/metrics, outbox age/pending, Go heap/goroutines, RabbitMQ per-queue metrics.
- Локальные Prometheus/Grafana: автоматически provisioned dashboard из 12 панелей и 5 alert rules.
- TLS policy, разделение миграции и runtime, workload S3/SQL policies и отдельный production template.
- Воспроизводимые генераторы выборок, RAM-gallery evaluation, сквозная acceptance, faults и backup/restore.

## Проверено

- Проинвентаризированы все 216 новых WAV: 20,30 часа, корректный входной формат.
- На галерее из 8 длинных файлов (63 минуты / 1,16 млн отпечатков) выполнены 576 RAM-запросов.
- На статической галерее найдено 205/216 копий длиной >=5 секунд; 2-секундные запросы не поддержаны
  при текущем минимуме подтверждённой длительности. Обнаружена ошибочная разметка общего контента.
- Через настоящий локальный MinIO/RabbitMQ обработаны все 216 запросов >=5 секунд: 214 duplicate,
  2 пропуска, p95 3,86 секунды / p99 8,85 секунды при 4 outstanding / 2 workers.
- Параллельный прогон двух независимых scope: 60/60 повторов, p95 около 2,04 секунды.
- Три SIGKILL-восстановления: service, RabbitMQ, PostgreSQL; 30/30 контрольных повторов успешны.
- pg_dump/pg_restore во временную БД: 7,69 млн отпечатков, ссылочная целостность сохранена.
- Проверена ограниченность publisher timeout при сетевом зависании Channel.Open после handshake.
- Unit/integration tests с race detector, go vet и go mod verify проходят.
- По API проверены готовый Grafana dashboard, пять правил Prometheus и фактические outbox/queue metrics.

## Что не объявляется завершённым

Локальная техническая часть готова для дальнейшего пилота, а не для обещания универсальной точности.
Остаются исследования/приёмка с участием владельца данных: ручная разметка неповторов,
короткие и зашумлённые случаи, повторно произнесённый текст, реальные фоновые помехи,
согласование целевых precision/recall. Два пропуска нового сквозного теста явно описаны в документации.

Нагрузочный профиль многопользовательского сервера, длительный soak, RPO/RTO, кластерные аварии,
реальные TLS endpoint/certificates и внешняя доставка alerts проверяются при переходе с локального
стенда на целевой сервер. Для этого подготовлены процедуры и шаблоны в [RELEASE.md](RELEASE.md).
