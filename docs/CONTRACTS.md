# События v1

## Вход

`schema_version` (по умолчанию 1), `task_id`, `track_id`, `s3_url`, `scope_id` (по умолчанию default).
Идентификаторы непустые, до 256 байт. Максимум JSON — 16 KiB. S3 URL должен иметь вид s3://bucket/key.
Поиск полностью изолирован по scope_id. Track ID должен обозначать одну неизменяемую запись.
В пределах scope task_id обозначает неизменяемую задачу: изменение любого поля отправляет событие в DLQ.
Повторная доставка той же задачи не обновляет время индексации и не создаёт новый результат.

## Выход

```json
{
  "schema_version": 1,
  "event_id": "стабильный SHA256 от scope_id и task_id",
  "task_id": "task-2",
  "track_id": "track-2",
  "scope_id": "default",
  "status": "duplicate",
  "algorithm_version": "landmark-v2-temporal-fft1024-hop256",
  "indexed_at": "2026-10-27T20:00:00Z",
  "match_details": {
    "original_track_id": "track-1",
    "query_start_sec": 0.032,
    "original_start_sec": 1.392,
    "matched_duration_sec": 4.2,
    "score": 0.72,
    "evidence": 189
  }
}
```

- unique: нет подтверждённого совпадения, информативные признаки сохранены.
- duplicate: обнаружен хотя бы один достаточно длинный совпавший фрагмент. Это не утверждение о повторе всего файла. Возвращается одно лучшее совпадение.
- insufficient_audio: слишком мало разнообразных признаков или недостаточная длительность. Индекс не записывается, результат публикуется штатно.

Score — покрытие выбранного интервала независимыми совпавшими временными кадрами, от 0 до 1;
это не вероятность. Evidence — число таких кадров. Границы приблизительные и обозначают область
поддержки признаками, а не точную границу слышимого звука. Конец исходного сигнала может не покрываться
из-за необходимости сформировать временные пары признаков.

Индексируются также частичные повторы, чтобы новый материал оставался доступным для поиска.
При одинаковом качестве предпочтительна более ранняя индексированная запись, затем track_id и offset.
Original track — ранее индексированная совпавшая запись; каноническое происхождение цепочек копий не строится.

AMQP MessageId равен event_id. Результат может прийти несколько раз после сбоя подтверждения;
получатель сохраняет обработанные event_id. traceparent переносится в AMQP headers.
Невалидные JSON/WAV, конфликт task_id и превышение размера идут в audio.tasks.dead.
Временные ошибки повторяются с ограничением, задаваемым quorum queue; перегрузку поиска нельзя
трактовать как unique. Схему и payload повторного запуска менять нельзя.

## Подтверждённый участок в длинном файле

После введения оконного поиска match_details описывает один подтверждённый участок,
обычно до 10 секунд при стандартных параметрах. Это свидетельство повтора; сервис пока
не возвращает все интервалы и не вычисляет полную долю повторного содержимого файла.
Минимум 2 секунды относится к длительности подтверждённого участка. Для запроса ровно
в 2 секунды после исключения граничных кадров подтверждение обычно короче порога;
проверенный рабочий диапазон запросов начинается с 5 секунд, устойчивее — с 10 секунд.
