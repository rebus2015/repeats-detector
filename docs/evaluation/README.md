# Оценка алгоритма

Проверка выполнена 28 октября 2026. Финальная версия: landmark-v2-temporal-fft1024-hop256.

## Реальная речь

Источник: локальная папка, предоставленная пользователем. 78 PCM WAV, 16 кГц, mono, 16 бит;
690.68 секунды. Исходники не изменялись и не включены в репозиторий. Производные данные игнорируются Git.
В text.txt найдены транскрипции всех 78 файлов; одинаковых полных транскрипций среди них нет.
Отрицательные пары пока размечены по разным исходным записям, без ручного прослушивания.
Отсутствие общего аудиофрагмента внутри этих пар не подтверждено вручную.

Разбиение воспроизводится по SHA256 исходника: 51 запись для разработки и 27 для контроля;
все преобразования одной записи остаются в одной части. Ранний неудачный v1 был измерен на обеих
частях. V2 и его пороги уточнялись на части для разработки; финальный контроль не использовался
для дальнейшего изменения порогов. Для независимой приёмки всё равно нужен новый корпус.

Обработано 858 случаев. Позитивные преобразования: точная копия, обрезка 5 секунд с позиции 1.357,
гауссов шум SNR 18/8/0 dB, G.711 μ-law, μ-law+шум 8 dB, AAC 24 kbit/s, AAC+шум 8 dB.
Все варианты приводятся обратно к PCM перед поиском. AAC подготовлен macOS afconvert.

Контрольная часть, финальные пороги:

Итого: TP=212, FN=31, FP=0, TN=54; recall 87.24%. Нулевое число FP на 54 парах не доказывает
нулевую вероятность ложного совпадения в эксплуатации. Максимальная ошибка оценённого сдвига
среди найденных позитивов — 32 мс. Границы совпадения остаются приблизительными.

На части для разработки: TP=392, FN=67, FP=0, TN=102 (recall 85.40%).
Coarse-вариант с 4 частотными бинами: TP=404, FN=55, FP=1, TN=101. Он не выбран по умолчанию.
Исходный v1 давал ложные совпадения на всех проверенных отрицательных парах и отклонён;
числа финального варианта приведены выше. Сгенерированные JSON-отчёты удалены при очистке проекта.

Параметры: минимум 2 секунды, 12 кадров с минимум двумя разными совпавшими хешами на кадр,
покрытие 0.08, разрыв до 0.8 секунды, допуск выравнивания ±2 кадра. Score не является вероятностью.
Гиперпараметры требуют повторной проверки при смене корпуса и условий записи.

## Воспроизведение

```sh
python3 tools/prepare_speech_corpus.py /path/to/wav-folder fixtures/speech
# На macOS добавить --aac для проверки AAC.
go run ./cmd/evaluate -manifest fixtures/speech/development.json -method landmarks
go run ./cmd/evaluate -manifest fixtures/speech/holdout.json -method landmarks
go run ./cmd/evaluate -manifest fixtures/speech/development.json -method landmarks-coarse
```

Если audioop недоступен в Python, μ-law варианты отсутствуют, и число случаев будет меньше.
Генерация AAC требует macOS с доступными системными кодеками. Manifest и inventory содержат
конкретные случаи, SHA256 и разбиение; полные отчёты можно сохранить локально.

## Синтетическая проверка и скорость

Синтетическая оценка вариантов landmarks, landmarks-coarse и exact-pcm — механическая
проверка, не оценка качества речи. Генератор и baseline точного PCM описаны в README проекта.
Файлы отчётов создаются повторным запуском утилит.

BenchmarkExtract на Apple M4 Pro / darwin arm64, Go 1.27.3: около 7.04 мс на синтетические
10 секунд PCM, 305596 B/op, 1376 allocs/op. Это только извлечение признаков, без S3, БД,
очередей и поиска; результат не задаёт пропускную способность сервиса.

Текущие проверки качества парные. Влияние размера галереи, длительных фонов, множества копий,
одинаковых фраз и реальных шумов ещё нужно измерить перед выпуском.
