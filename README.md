# Repeats Detector

Пакетная утилита ищет повторяющиеся фрагменты в аудиозаписях. Она принимает папку, обрабатывает файлы по имени в лексикографическом порядке и сохраняет результаты и акустические отпечатки в PostgreSQL. После записи результата утилита выводит его в консоль в формате JSON Lines.

## Входные файлы

Входные файлы имеют расширение `.pcm` и содержат монофонический G.711 A-law без заголовка, 8 бит на отсчёт, 8 кГц. Каждый байт — один отсчёт. Формат, частоту и число каналов у файлов без заголовка проверить невозможно.

Утилита читает обычные файлы непосредственно в указанной папке. Вложенные папки, символические ссылки и файлы с другими расширениями пропускаются. Максимальный размер файла составляет 128 000 000 байт.

## Запуск

Нужны Go 1.26+ и PostgreSQL. Для локальной БД можно использовать Compose. Скопируйте `.env.example` в `.env`, если локального файла ещё нет. Утилита читает `DATABASE_URL` из окружения, поэтому загрузите `.env` в оболочку перед запуском.

```sh
docker compose up -d --wait postgres
set -a
. ./.env
set +a
go run ./cmd/repeats-detector /path/to/audio
```

По умолчанию утилита создаёт таблицы при запуске. Если таблицы уже созданы и пользователю БД выданы только права чтения и записи, используйте `-migrate=false`. Параметр `-scope` задаёт отдельную область поиска. По умолчанию это `local`. Параметры указываются перед путём к папке.

## Структура проекта

| Каталог | Ответственность |
| --- | --- |
| [`cmd/repeats-detector`](cmd/repeats-detector/main.go) | Точка входа CLI. Читает аргументы и настройки подключения, перебирает файлы `.pcm` и выводит результаты в формате JSON Lines. |
| [`internal/audio`](internal/audio/pcm.go) | Декодирует G.711 A-law в знаковые линейные отсчёты на частоте 8 кГц. |
| [`internal/fingerprint`](internal/fingerprint/landmark.go) | Вычисляет спектры через FFT, выделяет пики и формирует отпечатки из пар пиков с привязкой к опорному кадру. |
| [`internal/matching`](internal/matching/match.go) | Проверяет кандидатов по временному сдвигу, длительности и плотности совпавших кадров. Возвращает лучший повторяющийся фрагмент. |
| [`internal/store`](internal/store/postgres.go) | Ищет кандидатов в PostgreSQL, вызывает проверку совпадений и сохраняет результат и отпечатки в одной транзакции. Встроенная [схема](internal/store/schema.sql) описывает таблицы `rd_tasks` и `rd_prints`. |
| [`internal/domain`](internal/domain/model.go) | Содержит общие типы для задания, отпечатка, кандидата, совпадения и результата. |

Для каждого файла CLI вызывает `audio` для декодирования, затем `fingerprint` для извлечения отпечатков. Пакет `store` извлекает кандидатов из индекса и передаёт их в `matching`. После сохранения результата CLI выводит его в консоль.

## Результаты

В `rd_tasks.result` хранится тот же JSON, который выводится в консоль. Поле `file` содержит абсолютный путь. Для повтора поле `match_details.original_file` содержит путь к предыдущей записи, а времена и длительность указаны в секундах.

- `unique` — в индексе нет подтверждённого повтора.
- `duplicate` — найден повторяющийся фрагмент.
- `insufficient_audio` — аудио декодировано, но отпечатков недостаточно для классификации.

Поиск использует ранее проиндексированные файлы той же области и версии алгоритма. Повторный запуск для того же абсолютного пути и содержимого возвращает сохранённый результат. Копия по другому пути обрабатывается как отдельная запись. Ошибки отдельных файлов выводятся в stderr, после чего обработка продолжается. Если хотя бы один файл завершился ошибкой, процесс возвращает ненулевой код.

Для одного файла поиск и индексация используют до миллиона первых отпечатков в порядке опорных кадров. Если отпечатков больше, обработка продолжается с этим префиксом. Одинаковые хеши в одном кадре записываются одной строкой.

У отпечатков для A-law 8 кГц своя версия алгоритма. Чтобы включить прежние записи в поиск, подайте их в поддерживаемом формате.
